# PieceOff web play client

A thin TypeScript/WebGL browser client for PieceOff Online (`rooms.pieceoff.app`).
The server (the rooms Worker) is the authority; this client draws what it says and
sends intents. The Rust core runs in the browser as a small WASM module
(`crates/pieceoff-web-wasm`) for piece outlines, board layout, name rules and the
protocol version, so the browser and the desktop app cannot disagree about geometry.
Design: [ARCHITECTURE.md](../docs/ARCHITECTURE.md) "Web play client".

## Layout

| Path | What |
| --- | --- |
| `src/app` | Lobby, create/join, board screen (lazy chunk), config, Turnstile |
| `src/gl` | WebGL renderer, camera, mesh/LOD, 2D overlays |
| `src/input` | Pointer events, gesture machine (drag, pan, pinch, long-press), hit testing |
| `src/net` | `RoomSocket` (join, resume, backoff) and `RoomState` (server-authoritative copy plus the drag overlay) |
| `src/media` | Built-in loop playback kept on the room clock |
| `src/ui` | DOM panels: toolbar, players, chat, host menu |
| `src/protocol.gen.ts` | Generated from the Rust types (below); do not edit |
| `wasm/` | Output of `build-wasm.sh` (git-ignored) |
| `public/builtin/` | The built-in puzzle loops (mp4 + jpg poster, `manifest.json`) |
| `dev/` | Renderer spike and dev page; never shipped |
| `e2e/` | Playwright two-client test (own `package.json`); never shipped |

## Build, test, check

```sh
web/build-wasm.sh          # core wasm into web/wasm (needs the wasm32 target and wasm-bindgen-cli 0.2.129)
cd web && npm ci
npm run typecheck && npm test
npm run build              # dist/play.js, dist/chunks/*, dist/play.css, dist/pieceoff_web_wasm_bg.wasm
scripts/web-check.sh       # all of the above + size budget + pack and check the tarball (~10 s warm)
scripts/web-e2e.sh         # two real browser clients against a local rooms Worker (opt-in, about a minute)
scripts/web-check.sh --e2e # both
```

The size budget (`size.mjs`, and again on the packed bytes in `check-pack.mjs`):
what the lobby loads up front (`play.js` and its static chunks, the wasm, `play.css`),
gzipped, must be at most 400 KB. The board is a lazy chunk (`chunks/board-*.js`),
reported but not budgeted.

## Configuration: `window.PIECEOFF_WEB_CONFIG`

Set by the host page before `play.js` loads; the bundle is site-agnostic. Unknown or
invalid values fall back to the defaults (`src/app/config.ts`).

| Field | Default | Meaning |
| --- | --- | --- |
| `api` | `https://rooms.pieceoff.app` | Rooms Worker origin (https, or http on localhost/127.0.0.1/[::1]); no trailing slash |
| `turnstileSiteKey` | the public `pieceoff-online` widget key | Turnstile site key for room creation |
| `assetBase` | `/play-app/` | URL prefix the bundle is served from; `play.css`, the wasm and `builtin/` are fetched from here. Trailing slash is added |
| `site` | `https://pieceoff.app` | Origin that serves `/join?c=CODE` invite links |
| `testHooks` | `false` | Only exactly `true` exposes the read-only `window.__pieceoffTest` probe on the board (snapshot, client id, camera, selection). For `web/e2e`; never set it on the site |

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
<link rel="stylesheet" href="/play-app/play.css">
<script>window.PIECEOFF_WEB_CONFIG = { assetBase: "/play-app/" };</script>
<script type="module" src="/play-app/play.js"></script>
<div id="pieceoff-play"></div>
```

(`play.js` links `play.css` itself if the page has not.) Chunks load relative to
`play.js`; the wasm and `builtin/` load from `assetBase`, so under a sub-path other
than `/play-app/` set `assetBase` to match.

## Protocol types after a protocol bump

`src/protocol.gen.ts` is generated by a Rust test from the `pieceoff-core` serde
types. After changing the protocol (and bumping `PROTOCOL_VERSION`):

```sh
PIECEOFF_UPDATE_PROTOCOL=1 cargo test -p pieceoff-web-wasm --test protocol_gen
web/build-wasm.sh && (cd web && npm test)
```

Without the variable the same test fails when the committed file is out of date.
This branch is on protocol v15. Turned pieces and difficulty arrive with v16: after
that merges, regenerate, then remove the `src/app/rotation.ts` shim paths.

## Release asset

```sh
web/pack.sh [--out DIR] [--no-build]   # -> dist/pieceoff-web-<version>.tar.gz
```

`<version>` is `version` in `crates/pieceoff-app/Cargo.toml`. The tarball root is the
`play-app/` directory: `play.js`, `chunks/`, `play.css`, `pieceoff_web_wasm_bg.wasm`,
`builtin/`, `play-app.json` (entry/css/wasm paths, version, protocol, sha256 per file),
`SHA256SUMS`, `LICENSE`, `THIRD_PARTY_NOTICES.txt`. Output is reproducible (sorted,
owner 0, fixed mtime, `gzip -n`). See [PACKAGING.md](../docs/PACKAGING.md) "Web client
release asset".

## How the site vendors a release

```sh
gh release download v<version> --repo <owner>/PieceOff --pattern 'pieceoff-web-*.tar.gz'
mkdir -p public/play-app && tar -xzf pieceoff-web-<version>.tar.gz -C public/play-app
(cd public/play-app && sha256sum -c SHA256SUMS)
```

Then the page (served from the site's own origin, e.g. `/play`) sets
`PIECEOFF_WEB_CONFIG` and loads `/play-app/play.js` as above. Check `play-app.json`'s
`protocol` against the Worker's `GET /api/info` `protocol`: they must be equal (a newer
Worker tells the client to reload, an older one to wait for the Worker deploy). Replace the whole directory on update (chunk file names carry content hashes).
